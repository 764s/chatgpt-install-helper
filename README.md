# ChatGPT 安装助手

面向 Windows 的非官方 ChatGPT 安装与更新工具。直接读取 OpenAI 官方生产渠道清单、下载官方签名的安装包，无需打开 Microsoft Store。

当前源码版本：**1.6.10**。这个版本号属于安装助手；待安装的 ChatGPT 版本在每次操作时实时查询。

## 功能

- **安装 / 重装、更新、仅检查更新**：显示本机版本、官方版本、进度及官方已公布的累计更新内容。
- **实时官方来源与缺包回退**：独立读取官方离线发布清单和 Store 发布标记，优先使用官方明确提供的包地址。明确缺包后，将其他官方候选按降序检查，最低到当前安装版本。两个界面区分已公布版本、可独立安装版本及来源范围。
- **先准备，再安装**：下载和校验期间可以继续使用 ChatGPT / Codex；默认准备完成后等待手动应用。
- **复用已有下载**：优先使用助手的有效完整缓存，也可以复用官方应用已下载、且符合实时目标版本的完整 MSIX 包，避免重复下载。旧官方缓存只作灰色提示，不作为安装目标。
- **断点续传与代理**：支持系统代理、HTTP 代理和 TUN，显示下载容量、速度与进度。
- **获取失败保护**：更新信息或包在重试、回退后仍获取失败时，只读核对 Codex 自带更新器。官方能取得相应更新信息或已准备好包时，提示更新途径可能变化、需要检查适配；保留原失败原因。
- **Codex 侧栏页面**：直接显示当前版本、实际可安装版本及操作按钮；下载中显示进度。可选“下载后自动安装并重启”，默认不勾选；详细原因折叠，底部提供小灰字“打开所在文件夹”。
- **双击即可使用**：自动保存独立副本并释放原 EXE，立即打开更新器；后台检测 Codex，插件未安装时添加、旧版时升级，同版或更高版直接跳过。保留启用 / 停用状态，开始和结束使用独立浮层提示，不阻塞原有界面。
- **覆盖重装**：不执行清空应用数据式卸载，不移除 ChatGPT Classic。

1.6.3 修复双击后无窗口的问题：已有后台进程时，按本地管道对应的进程恢复主窗口并核对实际可见性；后台模式由程序控制，避免隐藏启动标志覆盖用户后续的打开操作。兼容仍在运行的旧版后台，不中断当前下载或安装。

1.6.4 增加双击新版 EXE 后的插件版本比较和自动升级。安装及升级均在后台进行；已有插件使用 Codex 本地目录刷新，不通过重新添加改变启用状态。完成前核对真实安装版本、缓存中的启动路径和启用状态；查询失败或版本无法识别时停止配置，独立更新器仍可使用。

1.6.5 将插件安装 / 升级浮层绑定到更新器本体的客户区。即使复用另一个进程中的旧窗口，也随本体移动、隐藏和恢复；不再按鼠标所在屏幕定位。只读检查且无需变更时不弹浮层。

1.6.6 在插件实际升级成功并完成核验后清理旧助手副本及对应插件来源，只保留当前版本。只接管本规则新建并标记的版本目录，规则生效前已经保留的目录不受影响；旧进程占用、权限不足或目录出现外加文件时暂留并记入日志，下次插件升级再尝试。不会结束进程，也不添加定时清理任务。

1.6.7 区分“已是本次找到的最新可安装版本”“最新版缺包，但有较早版本可更新”和“有新版，未找到安装包”。仅 404 / 410 触发缺包回退；超时、权限、连接与服务器错误不当作缺包。准备完成及部署前重新运行同一选择流程，更高的包刚刚上线时停止原准备包部署。

1.6.8 接入当前官方客户端使用的 `windows-release.json`，以其离线包版本、架构和明确地址作为独立安装依据，显示“离线发布最新版”。Store 标记仅作发布进展参考，标记更高或读取失败均不阻断有效离线来源；离线清单不可读时才使用旧兼容路径。短暂连接失败重试一次，已读到的版本不因另一来源失败而丢弃。候选记录开始保留明确地址，兼容 1.6.7 的纯版本记录。

1.6.9 增加获取失败后的官方方式核对。只调用当前 Codex 提供的 `check_app_update`，不通过蓝点、旧日志或进程数量推断成功，也不触发官方下载或安装。核对结论是适配提醒，不是更新途径已经变化的证明；渠道或网络差异仍可能造成不同结果。

1.6.10 精简侧栏：主视图只保留状态、当前与可安装版本、必要的进度和操作。移除重复的“未下载”及常驻说明；来源、检查范围、缓存、后台兼容和完整错误统一放入默认收起的“详情”。重要错误或适配提醒保留一句短提示，自动安装及重启提醒只在相关操作时出现。右侧版本对应实际安装目标，其他渠道公布版本可在详情查看。

## 使用环境

- Windows 10 2004（19041）或更高版本、Windows 11；具体要求仍以最新 ChatGPT 安装包为准。
- x64 / ARM64 安装包自动选择；ARM64 尚未在独立设备上完成实际运行验证。
- 能访问 OpenAI 官方下载源的本地网络或代理。
- Windows 自带的 .NET Framework 4.x、Windows PowerShell 5.1 和应用部署组件。运行不需要 Python、Node、winget 或 .NET SDK。

实际部署需要 Windows 管理员授权，并可能关闭 ChatGPT / Codex。工具不检测任务是否结束；应用更新前请结束任务并保存工作。公司策略禁止应用部署时，仍需由 IT 授权。

## 从源码构建

克隆仓库后，在 Windows PowerShell 中进入仓库目录并运行：

```powershell
git clone https://github.com/764s/chatgpt-install-helper.git
cd chatgpt-install-helper
.\build.ps1 -OutputPath (Join-Path $PWD 'ChatGPTInstaller.exe')
```

构建脚本使用系统内置 `csc.exe` 与 PowerShell 组件，无 NuGet 依赖，不需要 Visual Studio 或额外安装 .NET SDK。脚本执行需符合本机 PowerShell 策略。

生成的 `ChatGPTInstaller.exe` 是单文件联网安装器，侧栏页面与图标已内嵌。双击后自动检查版本；点击“安装 / 重装”或“更新”先准备安装包，准备成功后再点击“立即安装 / 更新”。点击“仅检查更新”只查询版本、缓存状态和发布说明。

本仓库包含源码和文档，不包含 ChatGPT 安装包、离线许可证、个人配置、缓存或运行日志。自行构建的助手 EXE 没有商业代码签名；下载的 ChatGPT MSIX 保持官方签名。

## 添加 Codex 侧栏入口

1. 双击 EXE 即可打开更新器。本机已有 Codex 且插件尚未安装时，在后台自动添加；已有旧版插件时自动升级，同版或更高版跳过；原来的启用 / 停用状态保持不变。
2. 等当前任务结束后，完全退出并重新打开 ChatGPT。
3. 在侧栏“更多”中找到“ChatGPT 更新器”，按需固定。

真正开始安装或升级时显示对应浮层；成功后立即显示“已作为 Codex 插件安装”或“Codex 插件已更新”，说明版本和两种使用入口。失败会显示原因。提示不占用常规布局、不要求确认，结果 15 秒后收起；关闭进行中的提示不会取消安装，结果仍会再次显示。

原 EXE 将程序保存到 `%LOCALAPPDATA%\ChatGPTInstallHelper\App\{助手版本}`，启动固定副本后退出，释放原文件占用。原下载文件可删除，也可保留继续双击；请勿删除固定副本目录。未检测到 Codex 时可直接使用更新器，不把缺少 Codex 当作更新失败。

Codex 发现和安装状态查询均在后台，同版或更高版只执行一次只读插件查询；插件内操作完全跳过此流程。ChatGPT 的正常更新和助手内覆盖重装不会删除独立副本或插件来源，也不会隐式重新安装插件。移除插件后，再次直接双击 EXE 会按首次安装条件重新添加；仅在插件内更新 ChatGPT 不会触发添加。

入口位置由客户端管理，不替换官方更新蓝点。插件功能依赖当前 ChatGPT 随附的 Codex CLI 支持插件管理；不支持时仍可使用独立 EXE。需要修复配置时，可在“Codex 侧栏入口”页点击“添加 / 修复入口”；此手动操作会重新安装并启用插件。插件升级与当前运行进程分开：正在运行的旧窗口和插件会话继续工作，客户端重新加载后使用新版。

助手副本的清理只在插件从旧版成功升级到新版后触发；普通打开、同版修复、仅检查更新和更新 ChatGPT 均不触发。旧下载 EXE 发现已有新版时直接交接，不重新生成旧副本。移除侧栏入口仍保留本机助手文件；Codex 管理的插件缓存不由助手删除。

## 版本与缓存规则

每次操作独立读取官方离线发布清单 `windows-release.json` 与 Store 发布标记 `windows-store-update.json`。前者提供 `packageVersion` 和各架构的 `downloadUrl`，决定当前独立安装的发布范围；后者只作 Store 发布进展参考。优先核对离线清单明确给出的最新包，返回 404 / 410 后，再在该发布范围内按降序核对其他官方候选，最低到当前安装版本。离线清单不可读时，才按 Store 标记生成兼容候选继续检查。

官方客户端可通过 Microsoft Store 内部通道下载更新；Store 的蓝点与系统缓存不保证存在同版本公开 MSIX。本助手仍使用独立下载，不读取或修改 Store 内部缓存。离线清单读取成功时，界面明确将版本范围限定为“离线发布最新版”，Store 标记更高时另行提示；两份来源都失败时才报告无法读取版本。

目前未取得完整的 Windows 历史构建列表，因此不承诺遍历全部中间版本，不猜测构建号。`release-history-{架构}.txt` 从 1.6.7 起记录官方版本，1.6.8 起同时保留对应地址；旧的纯版本记录在读取时兼容。不扫描旧运行日志。记录只用于候选发现，每次仍须在线探测；记录读取失败会在日志说明，本次继续核对在线入口。选择结果及来源范围同时用于侧栏、独立窗口和检查报告。

清单版本与安装目标分别保存，下载包的身份、架构、版本和 Windows 签名必须匹配本次选定目标。准备后和实际部署前再次检查安装包可用性：即使清单号未变化，更高版本的包刚上线也会使旧准备状态失效。缓存复用与累计更新内容以实际可安装版本为准；没有可用包时，发布说明只作已发布内容参考。

缓存选择与准备流程由侧栏和完整窗口共用：

| 缓存情况 | 界面与行为 |
| --- | --- |
| 助手或官方已有符合本次可安装目标的完整包 | 显示“已下载，待校验”，点击“校验并准备”跳过安装包下载 |
| 仅有旧官方完整包 | 正常显示未下载，灰字提示旧缓存；按实时目标下载 |
| 助手有有效部分下载 | 可继续下载，重新核对续传身份 |
| 无可用缓存 | 正常下载 |

只复用当前用户官方应用的 `prepared.msix` 完整缓存。同卷优先建立硬链接，不支持时进行本机复制；不修改官方文件或更新状态，也不合并两端正在进行的下载，不保证官方反向复用助手缓存。缓存位置变化或校验失败时，按正常下载流程处理。

“仅检查更新”不复制、引用或下载完整安装包和许可证，也不执行安装。累计说明仅覆盖官方明确公布、能归属到版本批次的条目；缺失条目或获取失败不代表没有变更。

## 获取失败后的保护

保护在整次获取失败后触发一次，不为每个重试、已成功回退的候选或普通缓存未命中反复调用。覆盖版本来源读取、安装包获取与验证、离线许可证获取，以及仍需要更新但找不到包的情况；用户取消、普通本地文件读写或磁盘错误、系统部署失败及成功更新不触发；包内容或签名验证失败仍属于包获取校验失败。

| 官方核对结果 | 保护提示 |
| --- | --- |
| 已准备好更新，等待重启 | 获取信息或包失败时，提醒更新途径可能变化、建议检查并修复适配 |
| 确认有更新，但尚未准备好包 | 信息获取失败时提醒适配；包下载失败时只说明官方能发现更新，不能据此断言能下载包 |
| 无需更新、忙、不可用、错误或无法识别 | 不判定更新途径变化，保留原失败原因 |
| 官方属于其他发布通道 | 不据此判定当前生产通道需要修复 |

每次核对最多等待 12 秒，可以取消；不会改动自动下载来源、下载安装包、执行更新或重启。窗口、侧栏及日志保留各自的失败原因和核对结论，新操作开始后清除上次结论。

官方检查连接依赖当前 Codex 提供的本机会话上下文。插件将上下文通过同用户命名管道传给助手，仅在内存保存；独立 EXE 没有有效连接、Codex 已关闭或接口不可用时，明确显示“未能交叉核对”，不误报官方检查成功。旧后台尚不支持此保护时，页面会说明需重新打开新版后台。
